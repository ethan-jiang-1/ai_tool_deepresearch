## 阅读约定

**① 术语用英文 token**

这一层会大量出现 `work_id`、`check.next`、`missing_contract` 这类名字。原因是：**代码、日志、错误信息里出现的就是这些词**，换成中文反而对不上。

如果你在某一篇里遇到不认识的名字，去 [06 · 术语与速查](./06-术语速查.md) 查——那里是「中文说法 → 代码里的名字 → 大白话」的对照表。

**② 每一篇末尾都有「想动手看看」**

写着这一篇讲的东西对应哪个文件。表里的路径都相对框架目录 `DEEP_RESEARCH_HARNESS/`（01 篇的相对仓库根）。

**③ "代码强制的"和"靠自觉的"会分开写**

这是这套系统里最值得学的一点。每一篇都会明确区分：哪些是程序真的拦得住的，哪些只是写在文档里靠自觉的。

**别跳过这部分**——它决定了这套东西的可信度边界在哪。

---

## 一句提醒

这一层讲的都是**机制**。但机制不是这套系统最值钱的部分——**对"什么该交给代码、什么该留给人"的那条分界线，才是。**

如果读到最后你只记住了一堆名词，那多半是读法不对。建议随时回头问一句：

> **这一步为什么不让 AI 自己判断？**
> **这一步为什么不让程序自动做？**

这两个问题的答案，往往比机制本身更重要。
