# Subagent Node Contract (delta)

> req: SNC-001, SNC-002, SNC-003

## Purpose

为 sub-agent 增加 lifecycle logging 的强制契约与 relay driver 供需接线：sub-agent role spec（always-loaded）与 `taskMarkdownForSlot` 生成的 `task.md` SHALL mandate 读 `_beacon.json` + 经 `log-event.mjs` 发射 lifecycle 事件 + 事件带 nonce；phase workflow node SHALL 指示 Phase Agent 经 `drive-relay-slot` 驱动 relay。把 logging 指令从 dead code（`buildSpawnPrompt`）下沉到任何 spawn 路径都能读到的契约，使 logging 真正在 runtime 活过来。

## ADDED Requirements

### Requirement: Sub-agent role specs SHALL mandate lifecycle logging

Each sub-agent role spec (`subagent-dpt-source-intake.md`, `subagent-dpt-evidence-extractor.md`, `subagent-dpt-topic-scout.md`, etc.) SHALL mandate that the sub-agent read its slot's `_beacon.json` and emit the lifecycle event set (`search_start`, `search_done`, `fetch_done`, `file_written`, `error`, `work_done`) via `log-event.mjs`, carrying the beacon `receipt_nonce`. This contract SHALL be always-loaded (in the role body / `requires`), not only delivered via spawn prompt, so that any spawn path leaves trace.

#### Scenario: Role spec mandates beacon read + logging
- **WHEN** a sub-agent loads its role spec
- **THEN** the role spec SHALL instruct it to read `<slot>/_beacon.json` for `bundle_dir` / `log_cli` / `receipt_nonce`
- **AND** SHALL mandate emitting the lifecycle event set with the nonce

#### Scenario: Logging mandate is independent of spawn path
- **WHEN** a sub-agent is spawned via the driver OR via a hand-written Phase Agent prompt
- **THEN** the role spec's logging mandate SHALL still apply (it is loaded from the role spec, not only the spawn prompt)

### Requirement: taskMarkdownForSlot SHALL include the lifecycle-logging directive

The slot `task.md` generated by `taskMarkdownForSlot` SHALL include a directive that the sub-agent read `_beacon.json` and emit lifecycle events via `log-event.mjs` with the nonce. This guarantees the directive travels with the slot task even if the spawn prompt is not the engine-generated one.

#### Scenario: Generated task.md carries logging directive
- **WHEN** `taskMarkdownForSlot` writes a slot's `task.md`
- **THEN** the task body SHALL contain the beacon-read + lifecycle-logging directive
- **AND** SHALL reference the absolute `log_cli` path indirectly via the beacon (not hardcoded bundle path)

### Requirement: Phase workflow nodes SHALL direct the Phase Agent to drive the relay via the driver

The phase workflow nodes that perform delegated search/evidence work (`phase-wave0.md`, `phase-wave1.md`, and the Wave2 search-delegation section) and/or `shared-subagent-protocol.md` SHALL instruct the Phase Agent to drive the relay slot lifecycle via `drive-relay-slot` (`stage` → spawn → `commit` → `merge`) for delegated sub-agent work, rather than hand-orchestrating engine calls or hand-writing slot artifacts. This wires demand to supply (Decision 4): the driver (`subagent-relay-driver`) is the directed runtime path, not merely an optional one, so staging / beacon / commit actually occur and logging comes alive.

#### Scenario: Phase node names the driver as the relay path
- **WHEN** the Phase Agent loads a delegated-search phase node (wave0/wave1, or Wave2 search delegation)
- **THEN** the node body (Execution Brief / relay section) SHALL direct it to use `drive-relay-slot stage/commit/merge` for the relay slot lifecycle
- **AND** SHALL NOT instruct hand-orchestration of `stageSubagentSlots` / `commitSlotResult` or hand-writing of slot files

#### Scenario: shared-subagent-protocol points to the driver
- **WHEN** `shared-subagent-protocol.md` is loaded by the Phase Agent
- **THEN** it SHALL reference `drive-relay-slot` as the driver for the collect-as-return loop
