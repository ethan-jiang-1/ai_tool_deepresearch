## Context

See [proposal.md](proposal.md) for the motivating observations. The existing native finalizer already has one deterministic verdict path: every `event: check` with `source: playbook` participates in `verdict_mode: all`, and `required_checks` establishes the minimum declared set. Therefore a failed Phase-Gate check cannot safely remain a playbook verdict event merely because it is removed from `required_checks`; it would still turn an `all` verdict into FAIL.

`run-fixture-backed-case.mjs` currently runs a Wave0 Gate for every real source-intake canary, including case-604 where the Gate is not part of its declared claim. case-406 makes that Gate a required check even though its local setup deliberately lacks the Phase-owned `wave0_evidence` projection. case-221 similarly records a Wave1 Gate as a native check although its actor fixture establishes work-unit envelopes rather than a complete Wave1 Phase state.

The direct Sources of Record remain unchanged: Actor-owned bytes and Engine submit/ledger/index/trace establish an actor checkpoint; Phase-owned canonical artifacts and the Gate's own evaluation establish Phase readiness. No new persisted state, schema field, writer, or runtime command is needed.

## Goals / Non-Goals

**Goals:**

- Make each real-actor canary's required native checks match the exact bounded claim it presents to a reviewer.
- Preserve fail-closed Engine submit, receipt, ledger, inspect, and Gate contracts while preventing a missing Phase projection from misclassifying a completed actor handoff.
- Keep a reviewer-facing stop point: native actor PASS means the bounded actor checkpoint passed; Phase readiness remains unclaimed until a Phase-ready playbook runs its Gate.

**Non-Goals:**

- Change any Gate rule, phase transition, canonical projection grammar, research quality threshold, or production runtime contract.
- Add an Actor/Phase reconciler, a generic `--skip-gate` option, fallback/retry logic, a new health state, or fixture materialization of semantic artifacts.
- Treat a deterministic helper test, an old run, or a Playbook-Agent's own output as fresh real Subject Actor evidence.

## Decisions

### 1. Declare two checkpoints without adding a new runtime state

An actor canary's reader question is "did the named Subject Actor finish its declared work-unit checkpoint?" The answer is bounded by generated task/beacon, Subject-owned result/receipt/output/cache paths, Engine submit, submitted ledger, trace, and applicable work-unit inspect. A Phase Gate asks a different reader question: "are the complete Phase-owned canonical inputs ready?"

This preserves the distinction that changes the answer while using existing facts. Native completion remains the canary outcome authority, and the Gate remains the Phase authority. We reject a shared `phase_readiness`/`canary_status` projection because it would duplicate both facts and invite an ambiguous third verdict.

### 2. Remove the unconditional Gate path instead of making it optional

The shared real-source-intake helper will no longer invoke `check-gate-wave0-complete.mjs` after actor submission. case-406's `wave0-gate-pass` required check and its playbook Gate step will be removed; case-604 consequently no longer leaves an unrelated Gate attempt for Supervisor health to interpret. The same deletion reaches case-605 through the shared helper, so its containment playbook will stop claiming that the helper runs a Wave0 Gate; its declared submit and containment checks remain unchanged.

An optional helper flag or a synthetic "diagnostic Gate" would keep an unnecessary branch and, if it emitted a `source: playbook` check, could still alter `verdict_mode: all`. Dedicated Phase-ready playbooks already own Wave Gate coverage, so deletion is the shortest legal loop and removes rather than adds control complexity.

### 3. Make case-221 finish at submit plus work-unit inspection

case-221 retains two real `dpt-evidence-extractor` actors, generated task evidence, dry-submit/formal-submit evidence, ledger proof, and `operate-work-unit inspect`. Its native required checks will no longer include `wave1-gate`; its Markdown flow will not invoke the Wave1 Gate or emit a Phase completion event solely for this actor canary.

The rejected alternative is to have fixture JavaScript build the missing Wave1 semantic projections so the Gate can pass. Those projections belong to Phase Agent semantic work; generating them in a helper would turn deterministic setup into a hidden research controller and make a test-shaped success claim.

### 4. Keep deterministic verification separate from real-Actor proof

Focused tests may use fixture-generated bytes only to prove helper/checkpoint selection and no-Gate behavior. They will label that scope as deterministic contract evidence. The retained heavy cases remain the only `agent_flow_e2e` route for the real Actor claim and may honestly be `NOT_RUN` when their native actor/runtime is unavailable; that result is never upgraded by the deterministic tests.

## Risks / Trade-offs

- [A reviewer mistakes actor PASS for Wave readiness] -> Playbook body, frontmatter required checks, and delta specs state the explicit stop point and preserve Wave Gate proof in Phase-ready cases.
- [A future helper reintroduces a playbook Gate check] -> Focused regression asserts no unconditional helper Gate invocation and no actor-canary Phase Gate required check.
- [The narrower canary misses a Gate regression] -> Existing dedicated Wave playbooks retain the Gate contract; this change neither weakens nor substitutes for them.
- [A real-actor run is unavailable] -> Record `NOT_RUN` with the host/actor boundary in apply evidence; archive verification remains bounded to deterministic implementation evidence and does not claim actor behavior.

## Migration Plan

1. Update the three capability contracts and verification plan before target edits.
2. Remove only actor-canary Gate required checks/invocations and document the actor checkpoint stop point.
3. Run focused deterministic tests and the selected real-actor canaries where the host/runtime permits; record each claim as PASS, FAIL, or NOT_RUN with its proof boundary.
4. No runtime data migration or rollback procedure is needed. Reverting this scoped change restores only the former experiment contract; no production bundle state changes.

## Open Questions

None. The choice to keep Phase Gates in Phase-ready playbooks rather than fixture setup follows the existing ownership boundary and does not require a user semantic decision.
