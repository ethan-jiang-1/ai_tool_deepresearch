# Apply Evidence

## Evolution Direction Review

The implementation follows `evolution-helper-oriented-agent` and `evolution-simple-reliable-control`:

- One pure actor evaluator and one read-only queue-front preview feed the existing claim transaction.
- The Agent performs the real native observation and mechanically executes an accepted single fallback; the Engine validates the closed combination and preserves submit authority.
- The user is involved only for an external host/account/permission action the Agent cannot perform.
- No probe service, token, TTL, cache, database, registry, daemon, watcher, scheduler, fallback queue, global actor mode, new lifecycle state, or new trace family was added.
- A five-item unavailable batch now creates zero work IDs and zero queue/index/work-unit authority mutation, deleting the prior cleanup chain of five doomed attempts.
