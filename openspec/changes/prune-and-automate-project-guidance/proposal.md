## Why

Change A centralized project guidance under `openspec/` and closed the path/role migration, but
post-migration observation shows that the mandatory Charter + Context entry is still 866 lines /
6,194 words, only 18 lines below the previous baseline. `openspec/README.md` is also a 165-line
control map with an 11-document reading sequence and a glossary, so it does not yet give a reader
a short demand-driven route. Source: `_backlog/plans/centralize-project-guidance-under-openspec.md`
and its progressive tracker, P5 / E-010 / D-010.

The next change should remove duplicate explanatory truth and protect only deterministic guidance
topology facts, while preserving the accepted root and Harness entry routes, operation guidance
delivery through `openspec/config.yaml`, and the distinction between Agent judgment and Engine
verdicts.

## What Changes

- Apply constitutional admission review to the Project Charter and retain only the mandatory,
  implementation-neutral project core; move task-specific detail behind precise pointers.
- Reduce `openspec/README.md` to a role/trigger router, remove its competing glossary/reading-list
  role, and make demand-driven model and operation selection explicit.
- Build a duplication map for Charter, root `CONTEXT.md`, OpenSpec config, model canon, and
  operations; leave one full owner per meaning and only compressed orientation at non-owning
  surfaces.
- Review model and operation documents for a bounded reader question, trigger, authority limit,
  and completion boundary; retain, narrow, rename, or remove a document only when the review
  supplies a canonical owner and current links remain valid.
- Add focused deterministic coverage for current canonical guidance topology, role frontmatter,
  internal links, duplicate mirrors, old-path references, and entry-route synchronization. It
  will not make semantic-quality or research-judgment claims into Engine verdicts.
- Preserve all canonical paths established by Change A, Harness runtime behavior, and the existing
  `.agents/skills/**` and `.claude/skills/**` assets. Project-specific feedback-lifecycle guidance
  remains configuration-delivered through `openspec/config.yaml` and `openspec instructions`.
