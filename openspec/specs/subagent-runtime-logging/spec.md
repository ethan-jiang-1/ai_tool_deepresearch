# Subagent Runtime Logging

> req: SRL-001, SRL-002, SRL-003, SRL-004, SRL-006

## Purpose

Sub-agent lifecycle observability contract. Defines which lifecycle events a sub-agent MUST emit in its isolated context, how they are written via `log-event.mjs`, how they carry the `_beacon.json` nonce, and how they serve as Layer-2 execution-proof signals for provenance forensics.
## Requirements
### Requirement: Sub-agent SHALL emit lifecycle events via the log-event CLI

Sub-agents SHALL emit lifecycle events that bind to the assigned work unit. Required event payloads SHALL include `work_id`, `queue_item_id`, `kind`, and `receipt_nonce` when emitted for delegated work.

#### Scenario: lifecycle event includes work-unit identity

- **WHEN** a sub-agent emits `file_written`
- **THEN** the event SHALL include the assigned `work_id`
- **AND** it SHALL include the same `receipt_nonce` as the work-unit beacon

### Requirement: Sub-agent SHALL read _beacon.json for runtime coordinates

Sub-agents SHALL read `_work_units/waveN/{work_id}/_beacon.json` for runtime coordinates and nonce binding. The beacon SHALL identify the work unit, queue item, kind, bundle, log CLI, result schema, and receipt nonce.

#### Scenario: beacon path is work-unit path

- **WHEN** a sub-agent is spawned for a work unit
- **THEN** its task SHALL point to the work-unit `_beacon.json`
- **AND** it SHALL not rely on a non-work-unit beacon as production authority

### Requirement: Lifecycle events are the execution-proof signal for provenance forensics

Lifecycle events SHALL remain execution-proof signals, but gate authority SHALL require successful work-unit submit and ledger coverage. Lifecycle events are cross-check evidence for `work_unit_submission_presence`, not independent pass coverage.

#### Scenario: lifecycle events alone cannot pass gate

- **WHEN** lifecycle events exist for a work unit but submit has not appended a ledger row
- **THEN** the gate SHALL fail delegated coverage
- **AND** inspect MAY use those events to diagnose the incomplete attempt

### Requirement: Lifecycle events SHALL carry the work-unit beacon nonce

Lifecycle events SHALL carry the work-unit beacon nonce. The nonce SHALL be generated by the Engine during claim and SHALL be stored in the index, manifest, beacon, task, receipt events, result, and ledger.

#### Scenario: nonce is verified during submit

- **WHEN** runtime receipt events carry a nonce that differs from `_beacon.json`
- **THEN** `operate-work-unit submit` SHALL reject the result

### Requirement: Late submit rejection SHALL be logged

When a submit targets a `failed`, `timed_out`, or `abandoned` work unit, the Engine SHALL emit a late-submit rejection diagnostic with `work_id`, terminal status, terminal reason, and runtime refs when available.

#### Scenario: timed-out late submit is logged

- **WHEN** a timed-out work unit submits a result after retry has been claimed
- **THEN** submit SHALL fail closed
- **AND** the log/trace SHALL contain a late-submit rejection diagnostic

### Requirement: Runtime receipts SHALL identify the claimed execution actor class

Runtime receipt events for newly claimed work units SHALL carry `actor_contract_version: "work-unit.actor.v1"` and `execution_actor_class` equal to the Engine-owned claimed record. Receipt validation SHALL treat those fields as identity binding: missing or conflicting version/class SHALL reject submit for new claims. Receipt events SHALL NOT repeat the availability observation. The actor class SHALL distinguish `delegated_subagent` from `phase_agent_fallback`; runtime platform/session/spawn references remain optional diagnostic metadata and SHALL NOT determine actor class.

Legacy claimed attempts without an actor-class contract MAY use the truthful `legacy_unrecorded` compatibility path defined by delegated-work-units, but new normal/fallback attempts SHALL never use that compatibility path.

#### Scenario: Delegated receipt carries delegated actor class

- **WHEN** a newly claimed `delegated_subagent` work unit emits lifecycle receipt events
- **THEN** each submit-counted event SHALL carry `execution_actor_class: delegated_subagent`

#### Scenario: Fallback receipt does not impersonate subagent

- **WHEN** the Phase Agent executes a work unit claimed as `phase_agent_fallback`
- **THEN** each submit-counted receipt event SHALL carry `execution_actor_class: phase_agent_fallback`
- **AND** receipt validation SHALL reject `delegated_subagent` for that work ID
