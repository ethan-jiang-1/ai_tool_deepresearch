# BUG-051: 手动修改 ledger 触发 gate 级联 distrust，越修越坏

## 严重程度
P1 — 无修复出口。当 gate 因单一规则（如 `shared_ref_count_floor`）无法通过时，Agent 尝试通过手动编辑 `rb_output_declarations.jsonl` 来补救，但 gate 的 provenance 检查是全链路的——一次手动干预触发 work-unit index → manifest → result → receipt → beacon → output → cache → hash 全链 distrust，导致 gate failure 从 2 条规则暴增到 7 条。Agent 进入了"越修越坏"的正反馈循环。

FAIL: content_dedup

## 根因分析

### Gate 的 provenance 模型是全有或全无的

Gate 不只是检查"文件在不在"——它验证整条委托链：

```
operate-work-unit claim
  → work-unit index (_work_units/wave0/*/manifest.json)
    → task.md（queue_item_id, work_id, receipt_nonce）
      → _beacon.json（identity binding）
        → sub-agent 写入 output files + cache trails
          → runtime-receipt.jsonl（lifecycle events, receipt_nonce 一致）
            → result.json（identity fields + hash）
              → operate-work-unit submit
                → rb_output_declarations.jsonl（ledger row, result_hash, ledger_record_hash）
                  → gate cross-check: work-unit index ↔ ledger ↔ filesystem
```

任何一环的手动修改都会破坏 hash chain，gate 的 cross-check 检测到不一致后不是"降级信任该行"而是" distrust 全部 ledger rows"。这是一个合理的安全设计（防止伪造 provenance），但在 gate 卡住时变成了陷阱——Agent 无法通过手动修复 ledger 来让 gate 通过，尝试手动修复只会触发更多 distrust。

### 为什么 Agent 会尝试手动修复

Agent 被训练为"gate fail → 读 inspect/advice → 修复 → rerun"。当 advice 指向的问题（如"创建 00-shared-*.md"）无法通过正规 work-unit 路径解决时（queue 卡住、claim 阻塞），Agent 退而求其次手动创建文件 + 修改 ledger。但 ledger 不是为手动编辑设计的——它的 hash chain 要求所有 entry 必须通过 `operate-work-unit submit` 产生。

### 缺失的护栏

1. `rb_output_declarations.jsonl` 没有 "DO NOT EDIT" 头注释或文件权限保护
2. Gate advice 没有检测到"当前 ledger 已被手动修改，请停止手动修复，回滚到上一个 known-good state"
3. Phase MD 没有警告 Agent"不要手动编辑 ledger——这会触发级联 distrust"

## 建议修复

### P0 — 防止手动破坏

1. **`rb_output_declarations.jsonl` 增加完整性标记。** 在文件头或第一行写入 schema_version + 最后已知 hash，`validate-bundle.mjs` 检查文件是否被手动修改。或者最简单的方法：在文件顶部加注释 `# AUTO-GENERATED BY operate-work-unit submit — DO NOT EDIT`。

2. **Gate 在检测到 ledger 被手动修改时，给出不同的 advice。** 当前 advice 是通用的 "Repair work-unit submit/index/ledger drift"，但检测到手动修改时应给出："Ledger integrity check failed — manual edits detected. Restore rb_output_declarations.jsonl from git or known-good state. Do not hand-edit this file." Agent 读到 "Do not hand-edit" 后会停止尝试。

### P1 — 提供正规修复路径

3. **当 gate 检测到 ledger drift 时，提供 `--restore-known-good` 选项。** 从 work-unit index 和已存在的 result.json 重建 ledger rows（而非要求 Agent 手动修复）。

4. **修 BUG-048**（增加降级推进），使 Agent 不需要走"手动修 ledger"的歪路。
